## שלב 3 — הפרדת המסכים וביטול הפייפליין (החלטה 18.10)
**ארבעה מסכים נפרדים, כל אחד עם רשימה משלו, כמו מסך החשבוניות היום:**

| מסך | מה יש בו |
|---|---|
| חשבוניות | כמו היום |
| **תעודות משלוח** | חדש — כל התעודות, מכל דרך כניסה (מייל / צילום / הקלדה / דף) |
| **הזמנות** | הזמנות מספקים + הזמנות לקוחות |
| **כרטסות** | התאמת כרטסות, עם האלגוריתם החדש |

- **בלי שרשרת ובלי שלבים.** במקום הפייפליין: **קישור דו-כיווני** — בתעודה שמתאימה
  לחשבונית יש שדה שמצביע לחשבונית, ובחשבונית — לתעודה. ועליהן סטטוס פשוט
  ("מקושרת" / "ממתינה לחשבונית" / "ממתינה לתעודה").
- המערכת **מציעה** התאמה (אותו ספק + מספר תעודה שמופיע בחשבונית + סכום + תאריך
  קרוב), ובעלת העסק מאשרת בלחיצה.
- **תשלומים** — לא מתאימים ישירות עכשיו, אבל המבנה משאיר להם מקום (יש שינויים
  בדרך שם).
- הפייפליין לא נמחק מהמסד בבת אחת — העמודות נשארות כדי שאפשר יהיה לחזור; מפסיקים
  לייצר "שלדים" ריקים ומסתירים את השלבים.
- **סדר עבודה:** הדמיה של ארבעת המסכים → אישור → בנייה מסך-מסך.

## שלב 4 — כרטסות: אלגוריתם קשיח (18)
- ה-AI **רק מעתיק** את שורות הכרטסת; **הקוד מחליט**.
- זיהוי ספק בסדר קבוע: ח.פ → זהות שנלמדה משיוך ידני קודם → שם **מדויק** (או שם
  נוסף) → כתובת מייל. אין "דומה ל". שני מועמדים = לשאול, לא לנחש.
- השוואה **לתאריך הכרטסת**, לא להיום.
- השוואה **שורה מול שורה**: מה אצלנו ולא אצלם, מה אצלם ולא אצלנו, איפה הסכום
  שונה — וכל שורה לחיצה.
- כל שיוך ידני **מלמד** את המערכת, כך שבחודש הבא זה יזוהה לבד.
